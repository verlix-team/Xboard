# 原管理后台套餐国际化扩展

## 范围

修复目标是Xboard原管理入口，不是独立 `hop-admin-webui`。本地 `[开发完成]`、验收 `[部分通过]`；用户已明确授权提交、推送与测试部署，实际发布结果在下方另行记录。沿用已发布的套餐 fetch/save 翻译合同，不新增业务写接口、不改价格/权益/订单快照或数据库结构。

`public/assets/admin` 为固定产物子模块，只有编译文件，没有React组件源码。本批初始化已固定 `ef5f43da335092cbff8fdf0ad7ff9b4d92d7d0d7`，子模块工作树干净、gitlink不变；没有改写/推送上游子模块。

## 维护方式

- `OriginalAdminAssetService`严格校验原入口文件SHA256，再检查两处唯一集成锚点：在原套餐form顶部渲染编辑器；在原handleSubmit校验完成后合并翻译参数。
- `public/assets/hop-admin/plan-translations.js`是可维护扩展源码，复用原React与form实例。没有DOM推断、XHR/fetch拦截、Token读取、iframe或第二后台跳转。
- 原页面通过Blade加载带内容版本的新JS资产URL，HTTP路由组合扩展与原包；仍在原assets/admin/assets目录，保持Monaco Worker相对资源位置。组合不写磁盘或修改原产物。资源处理函数只读静态文件，不读取设置、账号或数据库；框架既有全局插件/运行时设置中间件仍保留，不宣称整个HTTP请求无需数据库。响应JS MIME/nosniff及内容版本永久缓存；版本改变即换URL。
- 固定包指纹或锚点不匹配时拒绝生成，不盲目给新上游包打补丁。升级固定子模块必须重新审查入口、React/form变量及唯一锚点，运行PHP/浏览器回归；不能仅更新gitlink便宣称国际化仍可用。恢复旧Blade/路由/服务版本即可撤去扩展，保留共享翻译表与历史快照。
- 使用原弹窗“提交”一次保存套餐与全部翻译，同事务/行锁/409保护保持在现有Controller；价格、流量、force_update参数不重新计算或改写。未迁移、缺版本或套餐上下文不匹配时前端阻止提交，不偷偷保留/猜测翻译。
- 中英俄独立名称/说明、唯一默认回退语言、显式原文导入、草稿保留、空语言删除。说明使用文本源编辑，支持既有Markdown/HTML/feature-support JSON；服务端检查各语言特性数量、顺序及支持标记。不是富文本渲染预览，不自动翻译。
