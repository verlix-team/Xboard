# 旧系统邮件英文模板

七种模板：`verify`、`mailLogin`、`notify`、`ticketReply`、`remindExpire`、`remindTraffic`、`smtpTest`。标题由 `EnglishMailDefaults` 维护，正文同时维护 `resources/views/mail/default/`、`classic/`。数据库同名记录优先；恢复默认使用内置英文。

管理 API 沿用 `/api/v2/{secure_path}/mail/template/{list,get,save,reset,test}` 及管理员认证，不在 Java 用户 API 增加管理路由。`get` 返回 `version`，`save/reset` 接受 `expected_version`，冲突 409。旧调用省略版本仍兼容，新编辑器始终携带版本。标题禁止换行和验证码/登录链接占位符，正文校验必要变量。

工单独立 `ticketReply`，标签英文、工单主题和回复保留原文。SMTP 独立 `smtpTest`。通知标题保留 `{{subject|Notification}}`，群发标题/正文由管理员提供，不自动翻译。界面语言不影响英文默认文案。

## 初始化与运维

容器 `/opt/hop-mail-release/initialize.php --check` 只读；`--apply` 需挂载新的受限备份目录到 `/backup`。只接受 `xboard` 库，备份目标七种记录后仅插入缺少记录；已有自定义内容保留，返回名称、ID 和摘要。中文自定义内容报告 `REVIEW_REQUIRED`。

无 DDL/Migration，不涉及 V053，不清理日志或历史队列。初始化后逐个失效七个 `mail_template:<name>` 缓存键，保存/恢复自动失效对应键。

使用 `deploy/docker/Dockerfile.mail-overlay`，`LEGACY_BASE_IMAGE` 为部署前核对的镜像 ID，`MAIL_SOURCE_REVISION` 为完整 Git SHA。只覆盖八个邮件 PHP 文件、十四个视图和初始化工具，保留队列/处理权补丁；构建一次、传输同一镜像、逐台只替换 Web。

发送结果保留既有 config 标记（仅 transport=smtp，无SMTP凭据），不改变该字段的现有行为。旧 `v2_mail_log` 没有config列，当前Laravel模型会过滤它；库中保存 email、subject、template_name、error 及时间戳。投递错误只记录异常类型；发送日志写入失败只做脱敏告警，不改变 SMTP 发送结果，避免成功邮件因审计故障重发。数据库日志和告警通道同时不可用时仍保留原发送结果；此时不保证有持久投递日志。SMTP 本身失败保留原有重试信号，不构成绝对“只发送一次”的保证。历史日志不改。回滚保留旧镜像/Compose；消费者和真实 SMTP 单独核对，不以 Web HTTP 200 代替收件。

`deploy/mail/verify-english-mail.php` 在真实只读事务中检查七种数据库模板、控制器版本、实际 Blade 回退渲染；不发邮件，只有显式 `--invalidate-template-cache` 才失效七个缓存键。

`deploy/mail/enable-mail-worker.py` 仅用于已授权的旧测试机2：确认精确镜像和两个队列的 ready/delayed/reserved 均为空，再新增 `/data/xboard-legacy-mail/compose.yaml` 的单个 mail 服务。复用既有 UID1000/网络/挂载，只消费邮件，不更改其他 Worker 或调度；失败只停止新服务，保留现场。回滚先停止该新服务，不删除/重放队列。

隔离测试：`LEGACY_MAIL_VENDOR=/path/to/vendor/autoload.php php /path/to/vendor/bin/phpunit --no-configuration --bootstrap tests/legacy-mail-bootstrap.php tests/Unit/Services/EnglishMailTemplatesTest.php tests/Unit/Services/EnglishMailTemplatePersistenceTest.php`。
