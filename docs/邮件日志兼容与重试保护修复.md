# 邮件日志兼容与重试保护修复

## 范围与状态

2026-10-14；基于 Xboard 邮件工作树 `f516a793b9d7f15228ab7ceaa766da46ee623684`，仅邮件日志保护及回归/发布工具/说明修改。功能 `[进行中]`、开发 `[开发完成]`、验收 `[部分通过]`。用户已授权本轮测试、提交推送test并部署旧测试环境两台PHP Web及专用邮件Worker；不发送测试邮件、不清理或重放历史任务、不改数据库结构/业务数据。

## 诊断更正

旧表没有 config 列属实，但“代码包含 config 就一定 SQL 报错”的推断不成立。当前旧邮件 Worker 使用 Laravel12.54.1；只读模型检查确认 MailLog 未解除属性保护、config 不可填充，fill 后属性只有 email/subject/template_name/error，没有 config。该检查数据库写入0、SMTP调用0，不能把主动查询不存在列产生的异常当成生产发信异常。

用户最终决定保留 config，不改它的既有值或行为。本轮只修复独立风险：SMTP 完成后，MailLog::create 抛异常会传回 SendEmailJob，使已发送邮件被当成任务失败。此风险用隔离故障注入复现，并非已确认线上发生重复发信。此前测试按代码预期补造 config 列不正确，现按真实旧表结构修正，同时验证返回结果仍保留 config、模型会过滤它不入库。

## 实现

- `app/Services/MailService.php` 保留修复前的 config 标记（仅 transport=smtp），真正SMTP配置不改；仅对发送日志持久化单独捕获异常。告警仅固定事件和异常类型，不含收件人、邮件正文、验证码、SMTP配置或异常详情。
- 日志与诊断通道同时不可用，不抛回已完成的 SMTP 操作；成功发送的 error 仍为 null，真实 SMTP 失败的 error 仍为原异常类型。
- 不改 SendEmailJob、扫描/执行处理权、队列名称、重试次数或任何邮件模板。不改 Java 找回密码流程/用户账号。
- 日志失效期间缺少数据库审计记录；单纯 SMTP 超时等未知结果的原重试策略仍存在，不能宣称端到端 exactly-once。
